Floodgate: a personal decision classifier trained on River

We turned Qwen3.6-35B-A3B into a calibrated yes/no classifier using only River's sampling and LoRA training, then trained it on 273 labels from one person's own browsing history. On pages it never saw, agreement with that person's labels went from about 66–69% to 77–80% in 8 River steps.

Team: cyu60, quachphu, TriNguyen1110, AdityaGaur77, atilavahedian · Code: github.com/cyu60/floodgate

The classifier

A Jev-style decision model, built from River primitives

Floodgate never generates text. Each question is a single prompt that ends in "Answer Yes or No." We ask River for one token with its top-20 logprobs and read the gap between "Yes" and "No". That gap is exactly the value Open-Jev uses to initialise its decision head (lm_head[Yes] − lm_head[No]), so the untrained base on River is Open-Jev at step 0. A single fitted temperature turns the gap into a calibrated probability.

score = logprob("Yes") − logprob("No") at the first answer token
P(yes) = sigmoid(score / T)

Our own labelled data

273 labels from one person's Chrome history

273labelled rows: 170 distraction, 103 work
50 of 120pages flip answer depending on the task
  1. Pulled the pages simple domain rules can't judge (1,678 ambiguous pages) and sampled 120: 45 YouTube/Wikipedia/X pages, 20 Google searches, 35 domains the rules had never seen, 20 rule-flagged distractions.
  2. Paired each page with two of four real tasks: building Floodgate, preparing a founder session, researching AI models, evening wind-down.
  3. An LLM teacher (Codex) drafted a P(distraction) and a one-line reason for each of the 240 pairs from a short profile of the person, and the person chose to use them as drafted. We added 33 labels the person made by hand.
  4. Split by page, not by row: 208 rows to train on, 65 held out, and no page appears in both.

No public data went into this model. The labels stay on the laptop; only the training rows went to River.

The training run

8 steps, about 2.5 minutes, no GPU of our own

River only trains next-token prediction, so we graded exactly one token. Each row becomes the chat-templated prompt (thinking off) plus a single target token, "Yes" or "No". Every prompt position has weight 0, so only the answer token is trained. A soft label p becomes two rows: "Yes" weighted p and "No" weighted 1 − p, which equals cross-entropy against the soft label.

For the River team

What would make this better on River

  • Exact logprobs for chosen tokensReturned logprobs are rounded coarsely (we saw "Yes" −0.63, "No" −1.00), so untrained scores cluster. A way to request exact logprobs for a list of token ids at one position would make every classifier like this cleaner and cheaper than top-20.
  • Custom loss or a scalar headOpen-Jev trains with candidate NLL plus a Brier term on a separate head. With cross-entropy only, we calibrate afterwards with a temperature. A Brier or softmax-over-candidates loss would close that gap.
  • Sharing a checkpointA teammate's River key gets Checkpoint not found for our checkpoint, so everyone reaches the model through one laptop. Granting another key access, or a small deployment on personal keys, would let a team share one personal model.
  • Latency for gatingAbout 4–8 s per decision on the shared pool is fine for a demo, but a browser gate wants under 1 s. A low-latency path for max_tokens=1 scoring would unlock real-time use.
  • DocsState the minimum Python version (3.9 has no wheel), document chat_template_kwargs={"enable_thinking": False} on chat_complete, and note that losses are summed over tokens.
